# 研究归档：5 / 15 分钟加密货币涨跌盘

**结论：没有可利用的优势，这个方向已经放弃，代码不再维护。** 留在这里是为了能复现结论。

- `short_cycle.py`：半小时内结算的市场快照，以及 5 / 15 分钟涨跌盘用分钟级历史价格做的回测
- `record_short.py`：秒级前向记录器（盘口 + 现货 + 结算结果）和回放报告
- 数据写在本目录的 `data/` 下（不进 git）

在项目根目录运行：

```bash
.venv/bin/python research/short_cycle/short_cycle.py            # 24 小时回测，大约 1 分钟
.venv/bin/python research/short_cycle/record_short.py --report  # 回放已记录的数据
```

## 市场概况

30 分钟内结算的市场几乎全是加密货币涨跌盘：BTC / ETH / SOL / XRP / BNB / DOGE / HYPE / ZEC 的 5 分钟和 15 分钟盘，再加上快到期的小时盘。结算规则：**窗口内 Chainlink 价格的 TWAP ≥ 开盘价 → Up**。流动性集中在 BTC（5 分钟盘单窗口成交中位约 $36K，ETH 约 $2K，SOL / XRP 只有几百美元）。加密货币盘的 taker 费率是 0.07，在 50¢ 附近约 1.75¢/股。

回测（最近 24 小时，1,532 个窗口）的结论：

1. **市场价本身很准。** 热门方的价格和它实际赢的比例基本一致；“跟热门”和“押冷门”扣完手续费都不赚钱。
2. **用现货价算的 TWAP 模型没有可靠优势。** 模型的 σ 用 Parkinson 估计，再乘一个放大系数 k（前一半窗口拟合，后一半测试）。它只是比“t 之前最近的市场价”准，但价格历史大约一分钟一个点，那个点中位已经过时 37 秒。换成“t 之后第一个市场价”，模型在所有时点上都更差；保守口径下，模型打法大多是负收益。
3. **Jev 不适合这类市场。** 这里比的是秒级的价格反应，没有可以判断的文字信息，Jev 也不擅长数字推理。
4. 想确认有没有延迟套利空间，需要逐笔的盘口和现货数据做前向记录，光靠分钟级的历史价格不够。见下一节。

## 前向记录（秒级）

```bash
.venv/bin/pip install 'websockets>=13'                # 可选：没有也能跑，只是现货只记 REST
.venv/bin/python research/short_cycle/record_short.py           # 一直记录，Ctrl+C 停；--minutes 60 记录 60 分钟后退出
.venv/bin/python research/short_cycle/record_short.py --report  # 回放已记录的数据（记录器在跑的时候也能看）
```

记录器每 2 秒一轮（`--interval`），只用公开只读接口，不下单：

- **盘口**：BTC / ETH / SOL / XRP 当前 5 分钟和 15 分钟窗口 Up 代币的最优买 / 卖价、那一档的股数、2¢ 以内的深度，一次 `POST /books` 拉全部 8 个。Down 的盘口就是 Up 的镜像（Down 卖价 = 1 − Up 买价），不用单独拉。下一个窗口的代币提前从 Gamma 拿好，换窗口不断档。
- **现货**：Coinbase websocket 的成交推送（`ws`，延迟几毫秒）。每轮记下发请求那一刻的最新价，逐笔成交另存一张表。REST ticker（`rest`）也照记，留作对照：它在 Coinbase 那边就比成交晚 0.6–0.9 秒，再加 1 秒 CDN 缓存。
- **K 线和结果**：每分钟补一次 Coinbase 分钟 K 线（模型的 σ 要用），窗口结束后去 Gamma 查结算结果。
- 出错只记日志：被限速（429）或连续出错时这一路暂停一会儿，websocket 断了自动重连。VM 暂停或断网之后，直接对齐到下一轮，不补拍。

回放（`--report`）：

- **同一秒的比较**：在和回测相同的时点（5 分钟盘 +1/+2/+3/+4 分，15 分钟盘 +5/+10/+14 分），用 `short_cycle.model_z / model_p` 算模型 P(Up)。k 用回测拟合的值，对这批数据是样本外。现价用和盘口同一轮拉到的 websocket 价格，窗口内各分钟的收盘价也用逐轮现货重采样。然后和同一轮的 Up 中间价比 Brier，再和 2 / 4 / 10 / 30 秒之后的盘口比。后者多看了几秒走势，本来就会更准，公平比较看“同一轮”。Brier 差的标准误按窗口聚类。
- **模型打法**：模型 − (卖价 + 0.07 × p × (1 − p)) ≥ 2¢、卖一至少 5 股才买，按真实卖一价成交。另有限价单口径：同一轮判断，N 秒后卖价没涨上去才成交。
- **领先滞后**：每轮现货涨跌 vs 盘口中间价变动的相关（websocket 和 REST 两路，用同一批轮次）。另外用逐笔成交做亚秒级的版本：两次盘口快照之间的中间价变动（CLOB 时间戳）vs 提前 δ 秒的现货涨跌（Coinbase 成交时间）。相关最高的 δ 就是盘口大约晚多少秒。

第一次前向记录的结果（2026-10-15，60 个已结算窗口：5 分钟 44 个、15 分钟 16 个，102 个时点；只算有 websocket 现货的约 40 分钟）：

1. **同一秒比较，盘口明显比模型准。** 模型 Brier 0.169，Up 中间价 0.123，差 +0.047 ± 0.012（按窗口聚类的标准误）。两者相差 10¢ 以上时（46 个时点），只有 11% 是模型更接近结果。
2. **模型打法亏钱。** 按同一轮的真实卖价买入、扣手续费后 ROI −53.5%（74 笔）；用 2 / 4 / 10 / 30 秒后的盘口也都是 −34% 到 −51%。
3. **现货不领先盘口。** 亚秒级领先滞后的相关在 δ = −0.25 秒最高，和 δ = 0 分不开；δ = +1 秒已经掉到一半左右。盘口和 Coinbase 成交几乎同时动，甚至略早。用 REST ticker 当现货时，盘口看起来领先一轮（2 秒），其中一部分是 REST 本身晚了约 1 秒。
4. 所以回测里模型比市场准，是历史价格过时造成的，对着 Coinbase 现货没有延迟套利空间。样本只有几个小时；要更有把握，就在一台不休眠的机器上连续记录几天。
